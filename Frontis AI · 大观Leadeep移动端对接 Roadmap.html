大观 × Leadeep 移动端对接 Roadmap

把 Leadeep App 作为大观移动端入口，大观统一承接租户身份、会话、文件、记忆与迁移资产；先打通可用闭环，再做迁移和统一记忆，最后升级为多渠道 ME。

无具体日期 · 按上线阶段拆分
产品定位 不是第二个 App；是现有 Leadeep App 内的大观移动端工作区。
身份底座 Leadeep C 端账号必须映射到大观 User / Tenant / Member。
一期目标 企业开通、App 进入、固定 session、Web/App 双向同步。
长期方向 Web、Leadeep、飞书共用同一套 ME 会话、文件和记忆治理。
V1

轻量打通

让开通用户能在 App 进入大观 Leadeep，并和 Web 同一会话双向同步。

V2

存量迁移

解决老用户接入大观后历史文件、知识库和关键会话资产断裂。

V3

统一记忆

Web 与 App 共用个人偏好、目标、任务结论、文件索引和专家调用偏好。

V4

多渠道统一

把 Web、Leadeep、飞书收敛为同一个 ME 多入口协作体系。

大观侧
开通 + 绑定
  • 企业后台开通 Leadeep
  • User / Tenant / Member 映射
  • 创建固定 leadeep_mobile session
  • 提供消息读写与增量同步
迁移 + 校验
  • 迁移任务与迁移范围
  • 历史会话归档可查
  • 文件进入统一文件服务
  • 迁移日志、失败重试、结果校验
记忆主数据
  • 个人记忆与目标记忆
  • 任务结论与文件索引
  • 专家调用偏好
  • 记忆来源、范围、编辑、停用
企业级治理
  • 企业知识库进入企业后台
  • Web 输入框统一选文件/知识
  • 多端 source_channel 与端能力
  • 权限、审计、离职/停用策略
Leadeep 侧
App 承载
  • 保留现有 App 主体验
  • 登录后识别大观绑定身份
  • 展示大观 Leadeep 入口
  • 消息写入/读取大观 session
源数据提供
  • 历史会话导出/读取接口
  • 文件与知识库导出
  • 迁移结果状态展示
  • 失败或部分成功明确提示
记忆消费
  • 调用大观记忆召回结果
  • 展示已记住/使用了记忆
  • 支持纠错或跳转管理
  • 携带移动端来源与可用能力
统一入口
  • 知识库入口切到大观数据源
  • 展示多渠道会话状态
  • 按租户权限控制可见范围
  • 保持一个 App 主体与能力开关
暂不做 / 边界
V1 边界
  • 不做 Web 端知识库选择
  • 不做企业级知识治理
  • 不做多个 Leadeep topic
  • 不做飞书同步与全量迁移
迁移边界
  • 历史原文可归档，不进长期记忆
  • 不做黑盒一次性脚本迁移
  • 迁移范围必须可配置
  • 失败项必须可追踪和重试
记忆边界
  • 会话原文仍按 session 隔离
  • 企业规则不由普通成员直接全员生效
  • 文件索引不替代文件本体
  • 专家公共记忆进入治理
工程边界
  • 不新建大观专属 App
  • 不长期维护双分支
  • 大观规则不下沉到 App 侧重复维护
  • 飞书作为后续渠道接入

先解决什么

先把“企业开通 + 身份映射 + 固定会话 + 双向消息同步”跑通，满足首批领导和标杆客户可用。

最大风险

如果大观和 Leadeep 各维护一套数据再互相同步，会快速变成补偿层；主数据必须收敛到大观。

评审抓手

每个版本只看三件事：用户是否能进入、历史是否不断裂、记忆和文件是否按权限共享。
