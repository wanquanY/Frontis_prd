# Frontis AI · 大观 Leadeep 打通需求列表

> 本需求列表按 `Frontis AI · V0.8 需求列表.md` 的口径整理。
> 核心范围：大观 Web 多 session 与 Leadeep 移动端绑定打通；企业后台给正常成员开放 Leadeep 权限；普通员工获得权限后可使用 Leadeep 移动端。
> 核心差异：历史记录是页面上看到的聊天消息、引用文件、输出产物和消息状态；Leadeep 与 Web 历史记录双向同步，飞书历史记录只从飞书单向同步到 Web，Web 续聊不回写飞书。记忆是 Agent 背后的统一机制，不等同于历史记录同步。

| 功能模块 | 一级功能           | 二级功能                 | 功能说明                                                                                        |
| -------- | ------------------ | ------------------------ | ----------------------------------------------------------------------------------------------- |
| 不做范围 | 独立移动端         | 新建大观 App             | 不重做一个独立的大观移动端 App，不把 Leadeep C 端完整产品形态搬进大观。                         |
| 不做范围 | 多会话管理         | App / 飞书内创建大观会话 | Leadeep App 和飞书都不创建、不切换、不管理大观多 session，只进入指定 Web 绑定会话。             |
| 不做范围 | 企业级知识治理     | 本轮不设计               | 本轮不设计企业级知识治理，不把普通成员表达的企业规则直接全员生效。                              |
| 不做范围 | Web 输入框知识选择 | V1 暂不做                | V1 不做 Web 输入框选择知识库/文件能力；后续如需做，应作为 ME 输入框统一能力，不只服务 Leadeep。 |

## 新增需求

| 功能模块                  | 一级功能             | 二级功能               | 功能说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------- | -------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 企业管理后台              | Leadeep 移动端权限   | 正常成员权限开放       | 企业管理员可为当前租户内状态正常的成员开放 Leadeep 移动端权限；普通员工获得权限后即可在 Leadeep App 内进入大观绑定会话；成员停用、移除或无手机号时需阻断或提示异常。                                                                                                                                                                                                                                                                                                      |
| 工作台                    | 移动端下载入口       | 用户卡片二维码下载     | 已开放 Leadeep 移动端权限的成员，在 Web 左下角用户卡片看到移动端下载按钮；用户 hover 后展示 Leadeep App 下载二维码，手机扫码进入下载页或安装引导。                                                                                                                                                                                                                                                                                                                        |
| Leadeep App、大观账户体系 | 账户体系打通         | 租户成员身份进入       | Leadeep 登录后通过手机号或统一账号标识接入大观 `User / Tenant / Member`；单租户直接进入，多租户要求选择租户，未开放移动端权限则不展示大观问策入口或提示联系管理员。                                                                                                                                                                                                                                                                                                       |
| 工作台、Leadeep App、飞书 | 会话绑定             | 绑定会话与历史记录同步 | 成员开放权限后创建或复用一条 Leadeep 问策绑定 Web session；Web 会话列表通过 `Leadeep` / `飞书` 标签标识绑定会话来源；点击进入后仍是普通聊天记录体验；Leadeep 与 Web 绑定会话显示同一份历史记录，App 与 Web 新增消息双向可见；飞书作为后续绑定入口时，飞书历史记录单向同步到 Web，Web 续聊不回写飞书；历史记录只指页面可见的聊天消息、引用文件和产物状态。                                                                                                                 |
| 工作台、ME 记忆、文件服务 | 统一记忆机制         | 记忆文件体系一致生效   | Web 普通会话、Leadeep 绑定会话和后续飞书绑定会话在同一 `User + Tenant + Member + Agent` 下使用同一套记忆文件体系，包括 `Agent.md`、`team.md`、`user.md`、`memory.md`、`session.md`、`file-index.md`、`agent-config.md`；每个用户使用的每个 Agent 都有独立文件体系，不同 Agent 默认不共享记忆；`team.md` 随 ME 工作台添加或移除专家自动同步专家 ID 和能力画像摘要；页面历史记录原文、临时文件全文和当前任务短期上下文仍按 session 隔离，只有确认后的内容才能进入长期记忆。 |
| 运营后台、迁移工具        | 交叉用户历史资产迁移 | 历史资产迁移           | 只处理“用户原先下载并使用过 Leadeep，后来又开通大观”的交叉用户；在确认 Leadeep 账号与目标大观成员身份后，支持迁移历史会话原文、文件型知识库、上传文件、重要产物和关键摘要；迁移需具备范围选择、执行日志、失败重试和结果校验。                                                                                                                                                                                                                                             |
| 飞书、工作台              | 多入口绑定预留       | 飞书绑定入口规则       | 飞书作为后续绑定入口时，只绑定 Web 指定会话，不创建、不切换、不管理大观多 session；飞书绑定会话使用与 Leadeep 一致的账户、会话、记忆和文件规则，差异只在历史记录同步方向。                                                                                                                                                                                                                                                                                                |

## 优化项

| 功能模块                            | 一级功能     | 二级功能                 | 功能说明                                                                                                                                                                                                                        |
| ----------------------------------- | ------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工作台、Leadeep App                 | 历史记录展示 | 连续工具调用折叠         | 当同一轮 Agent 回复中出现连续工具调用时，历史记录默认折叠为工具调用组，展示工具数量、状态、耗时和失败摘要；用户可展开查看工具名称、简要输入输出和失败原因；该能力只优化页面阅读体验，不改变历史记录同步、存储、审计和记忆机制。 |
| 工作台、成果详情、会话分析          | 分享弹窗     | 生成链接不展示预览       | 成果分享、对话分享和会话分析分享弹窗只展示链接生成状态、分享链接和复制按钮；不展示在线预览、不展示“使用 Frontis AI 创建”入口，内容查看回到分享页或成果详情页完成。                                                             |
| 企业管理后台、Leadeep App、迁移工具 | 异常状态     | 开通、同步、迁移失败处理 | 开通失败、身份冲突、消息写入失败和交叉用户迁移失败需展示明确原因与下一步动作；可恢复异常需支持重试，重试不得产生重复消息或重复迁移资产。                                                                                        |
