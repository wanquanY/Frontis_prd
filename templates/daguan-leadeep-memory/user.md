# user.md

王晨是 Frontis AI 的产品经理，主要负责大观 Web 端产品规划、PRD 编写、跨端打通方案和研发需求交接。他经常在公司用 Web 端拆版本需求，出差或会议间隙会用 Leadeep 问策追问历史 PRD 内容。

## 工作画像

- 职能：产品经理
- 高频任务：写 PRD、整理需求列表、画用户旅程、对齐原型、拆研发任务
- 常用入口：Web 端 ME、多会话工作台、Leadeep 问策
- 偶尔入口：飞书对话同步
- 常用文件：PRD、需求列表、原型说明、会议纪要、用户旅程图

## 表达偏好

- 喜欢先看结论，再看分层拆解。
- 不喜欢空泛概念和技术字段堆砌。
- 产品文档里要讲清楚功能效果、用户动作、页面呈现和业务规则。
- 不希望 PRD 里出现偏技术实现的账号字段。
- 对“历史记录”和“记忆机制”的区分要求很高：历史记录是页面可见消息，记忆机制是 Agent 背后的持续理解能力。

## 当前关注

- 大观和 Leadeep 打通后，普通企业成员也能使用移动端 Leadeep。
- 企业后台只要为正常成员开放 Leadeep 权限，用户就能登录移动端。
- Web 左下角用户卡片需要有移动端下载按钮，hover 展示二维码。
- 会话列表要能看出哪些是 Leadeep 会话、哪些是飞书会话，但不要展示“单向 / 双向”这种机制标签。
- Leadeep 与 Web 历史记录双向同步。
- 飞书只把对话记录同步到 Web，Web 续聊不回写飞书。

## 近期纠正

- “问策”不是“问测”。
- “Leadeep 权限”不是“问策权限”。
- Leadeep 问策会话不是用户手动绑定，是系统自动同步到 Web 端对应 ME 会话。
- 存量迁移只处理交叉用户：先用过 Leadeep，后来又开通大观的用户。
